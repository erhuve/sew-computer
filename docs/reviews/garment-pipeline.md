# Component garment pipeline review

2026-09-16. Implementation in an isolated checkout; not deployed. The active scope remains in [the software plan](../plans/software-prototype.md).

## Delivered implementation

The tool-free interpreter can now select an explicit relaxed drop-shoulder woven shirt construction and explain ordinary design choices without asking the owner to resolve every drafting detail. The strict schema exposes bounded component options and assumed design dimensions. Accepted choices remain editable; manual construction is available without a model. Original requirements and body measurements remain preserved.

The trusted compiler drafts four torso halves, optional flat-cap sleeves, bound sleeve underarm openings, button cuffs, separate placket/facing templates, collar stand/fall templates, curved back-tail hems and gathered front frills. It generates structured seam edges, exact sampled-edge lengths, assembly ratios, registration marks, button/buttonhole locations, grainlines, cut quantities, outward seam-allowance contours and explicit boundary finishes. Two-layer shell/facing templates and mirrored pieces are distinguished. Interfacing uses the named shell templates as disclosed in the derived material list.

Compiler-derived measurements, material/closure counts and ordered assembly instructions are separate from editable AI/owner specifications. The UI and tech pack include front/back construction schematics, explicitly not simulations. Patterns, specifications, choices and coverage belong to one immutable revision. Pattern disclosure controls derived dimensions and construction exports; importing derived sections cannot establish authority or overwrite editable specifications.

Digital coverage requires the selected piece inventory, connection inventory, dimensions and annotations. Requirement mapping remains model-assisted and can miss intent; the original brief remains the review reference. A partial base or unresolved requirement is not called complete. All outputs remain printable references requiring a toile, not cutting/fit certification.

## Independent adversarial review

Three review rounds identified and reproduced missing selected-piece acceptance, degenerate cut-contour acceptance, weak graph connectivity, incorrect assembly ordering and missing mark validation. The implementation adds exact selection-dependent inventories, contour area/containment/intersection checks, graph traversal, dependency-ordered instructions, seam registrations and closure mark counts. Tests mutate real generated output to exercise these failures. The reviewer independently confirmed closure of every finding, including deletion of registration or closure marks, and found no remaining high-confidence P1 finding in the reviewed scope or new interpretation/export/import privacy blocker.

The autosave race is separately covered: generation waits for the in-flight save and saves newer edits before publishing instead of dropping the click. UI, SVG and PDF thumbnails now use the same coordinate orientation.

A subsequent independent review reproduced selected button-spacing drift, schematic button-count disagreement, and acceptance of impossible closure placement. The compiler now preserves the selected front-button pitch instead of redistributing buttons. Generated schematics take front-button positions, neckline/hem paths and construction proportions from the pattern; preview proportions use available explicit inputs, with synthetic fallbacks when missing. Cuff and collar closures are shown separately. Closure validation checks positions, not just counts, and derived measurement values must agree with the actual geometry. Regression tests move closure marks, collapse a cuff closure onto itself, alter a derived circumference and exercise a flared torso. Shared preflight now explains shoulder/ease, armhole/length, flare, sleeve and cuff incompatibilities before starting the geometry worker, preserving the entered values.

The independent follow-up found no remaining concrete defect in those fixes, verified legacy base compatibility and pattern-redacted exports, and independently passed 42 sizing/export cases and both component-engine cases. This closes those findings, not the remaining general garment or physical validation scope.

## Verification and remaining gates

Final release-candidate verification passes 87 application tests, 24 engine tests and all 20 browser cases, plus typecheck, production build, documentation and whitespace checks. The full browser suite ran after the build completed; an earlier overlapping build briefly removed the test server's index file and is not counted as a passing run. The refreshed sample bundle uses the corrected custom-page renderer.

The final independent release review reproduced cropped mitered seam allowances in custom-size PDFs and the aggregate SVG for a short, strongly flared shirt. Page bounds now include the actual seam, cut, grain and mark extents, with a common translation that preserves millimetre scale. Component PDF pages also reserve enough width for their cutting instructions. The viewer uses the same full-contour layout principle, avoiding clipped and overlapping allowances. Independent regressions verify SVG vertices and piece separation, Poppler-rasterized PDF dimensions, and all 18 browser panel bounds. The reviewer confirmed both fixes. These changes do not alter pattern geometry or historical artifacts; new exports of old revisions preserve their original bytes.

The printing follow-up adds A4 and US Letter tiled PDFs to each new generation, including legacy base patterns. The existing custom-size PDF and SVG are retained. Tiles preserve millimetre coordinates, include outward allowance bounds when supplied, use 10 mm overlap and registration crosses, carry immutable input identity, and include a page/piece inventory, cutting quantities and a 100 mm calibration square. Printable marks identify seam registrations and closure centers; a buttonhole center is not a specified slit size. The guide explains mirrored left/right cutting and distinguishes unannotated legacy outlines. Pattern disclosure controls these files, which are stored as normal immutable artifacts and delivered byte-for-byte with checksums. Older revisions are not regenerated by exporting them.

Printing checks use an independent Poppler rasterization of A4 and Letter output to measure the calibration square and compare repeated pattern strokes across horizontal and vertical joins. Adversarial cases cover negative allowance coordinates, page-budget rejection, cancellation before/during rendering and absence of all tiled files from pattern-redacted bundles. This follow-up is a local adversarial review, not a new independent-agent review or physical printer calibration.

The printing pass verifies 87 application tests, 23 engine tests and all 19 browser cases across the full browser run and a corrected inventory-count rerun. Typecheck, production build, documentation and whitespace checks pass. The PDFs request no print scaling and single-sided output; printer dialogs may override those preferences, so the physical square remains mandatory. The refreshed eight-file example includes [A4 tiles](../verification/garment-pipeline/pattern-a4-tiled-live-pattern-3.pdf) (82 pages) and [Letter tiles](../verification/garment-pipeline/pattern-letter-tiled-live-pattern-4.pdf) (84 pages), including two guide pages each. Page counts are for separate piece templates, not a nested fabric cutting layout or yardage estimate. All delivery checksums are verified. It reuses the captured model interpretation, with no new model call.

The completed follow-up verification passes 87 application tests, 20 engine tests (18 legacy CPU/resource tests and two component/variant tests), and all 19 browser cases. Typecheck, production build, documentation and whitespace checks pass. The expanded component matrix covers all six synthetic XS–2XL fixtures and plain, short-sleeve, stand-collar and flared variants. These test construction relationships, not population coverage or fit evidence. Desktop/mobile browser evidence is under `docs/verification/garment-pipeline/`.

A live tool-free GPT-6 Astra interpretation of a white woven button-up with long sleeves, practical tails and tasteful frills chose a 70 mm curved back extension, 30 mm front frills gathered 1.5:1, a stand/fall collar, button plackets and cuffs. Using explicitly synthetic body inputs, it generated 18 connected templates and all six export files. The [sample tech pack](../verification/garment-pipeline/tech-pack.pdf) and [manifest](../verification/garment-pipeline/manifest.json) preserve that actual model-selected design; this is one live example, not an accuracy estimate.

The follow-up regenerated and validated all six sample export files from that previously captured interpretation, including its selected 85 mm button pitch. It did not make a new model call or treat this single example as broader interpretation coverage.

The component compiler deliberately does not implement set-in sleeves, fitted darts/shaping, split coat tails, pockets, arbitrary topology or broader lower-garment construction. Legacy skirts/trousers remain partial base patterns. Collar roll, turn-of-cloth, fabric behavior, wearer-specific neck/arm/wrist measurements, grading, cutting layout/yardage, printer calibration and physical fitting remain unvalidated. Digital tiled output does not establish printer accuracy. Schematics are illustrative rather than an assembled fabric model. The whole envisioned general-purpose garment system is not complete merely because this shirt compiler passes its digital checks.

Before deployment, install the updated locked engine runtime in the service checkout, complete all repository checks, and follow [private deployment](../deployment.md). Never build or test against the live data directory.
